# Bundle-splitting analysis (web build chunk-size warning)

## Context

The `[5/8] web build` stage (`scripts/build.mjs` → `vite build --config vite.web.config.ts`) emits Rollup's `chunks larger than 500 kB` warning. The offending chunk is `App-*.js` at **2.14 MB minified**.

Both build graphs inspected:

- Desktop renderer (`electron.vite.config.ts`): entry `index.js` = **4.1 MB**, loads from local disk via `file://`.
- Web client (`vite.web.config.ts`, root `src/web`): initial `index-*.js` = **236 KB** (login/probing screen), heavy app content lazy-loaded post-auth.

## What is already code-split

The mermaid diagram leaves are already dynamic imports — each diagram type is its own chunk loaded on demand:

- `cynefin-*.js` 687 KB, `cytoscape.esm-*.js` 443 KB, `katex-*.js` 259 KB, plus ~50 per-diagram chunks.

The web client stages loading deliberately:

1. `index-*.js` (236 KB) — RemoteApp, auth flow (probing / password / tailnet-identity), connection overlay.
2. `import('@renderer/App')` — the 2.14 MB App chunk — only after `sync-full` hydration / `ready`, in parallel with the WS handshake (`src/web/main.tsx:103`, `:233`).

## Assessment

The 500 kB threshold is a critical-path heuristic for web pages where the chunk blocks first paint. Neither target fits that model:

- **Desktop renderer**: loads locally; bundle size is irrelevant. Splitting adds complexity for zero benefit.
- **Web client**: first paint is the 236 KB login chunk; the 2.14 MB App chunk loads only post-auth, which is the right time.

## Recommendation

Do **not** split further. Further splitting (route-level lazy chat view, lazy react-markdown/diff) would:

- Add an extra fetch per split over a possibly slow tunnel in the web client,
- Complicate the desktop renderer for nothing,
- Buy at most a few hundred ms on already-auth-gated code.

If the warning noise matters, raise `build.chunkSizeWarningLimit` (e.g. 3000) in `vite.web.config.ts` rather than restructuring. Revisit only if the web client later gains multi-view navigation worth route-level `import()`.

## Follow-up flagged (out of scope for this task)

Desktop renderer `index.js` is 4.1 MB — mermaid + xterm + everything eagerly pulled by the entry. Moot for local load, but if startup paint ever regresses, that is the more interesting target than the web bundle.
