Claude tool cards — proposal v2

Revised after review: the Bash input block stays (long commands, and seeing exactly what ran is a security affordance — it is why Bash renders its input even when hide tool input is on); what changes is legibility, on both the input and the output. Everything here is engine-neutral: these are ToolKind bodies shared by Claude, Codex, opencode and pi, so no harness ends up looking like the odd one out. Only the name→kind maps and the per-tool descriptor table are Claude-specific.

1 · Header grammar — shared by every card, every engine

Status dot · tool name · the object of the action · metadata chips · chevron. Chips are derived from the result, never echoed input, and are the only thing a collapsed card gains. They are opportunistic: each engine fills what its wire carries and the rest simply do not render — Codex commandExecution has a real exitCode, Claude's Bash result does not, so Claude shows duration and Codex shows both.

3 · Bash — output colouring

Output is flat grey today: TerminalView renders ANSI escapes and nothing else, so a piped grep, rg, git diff or sed -n — none of which emit escapes when piped — arrives uncoloured. Proposal: when the output carries no ANSI (if it does, honour it and stop, the tool coloured itself), run four detectors in order.

The four detectors. 1 · grep/rg — a path:line:, path-line- or bare NNN:/NNN- gutter; the gutter renders muted and the content is highlighted by the file's extension through the existing EXT_TO_LANG map. 2 · unified diff — diff --git or an @@ hunk header, in the same palette the edit card uses. 3 · JSON — trimmed output starts { or [ and JSON.parse succeeds. 4 · single-file read — the command is one plain cat/head/tail/sed -n of one path, so the whole output takes that file's language.

Guards. ANSI output is never re-highlighted. Detection reads the first ~40 lines, not the whole buffer. Above a size cap (100 KB proposed) everything falls back to plain — colouring a 5 MB log is not worth the frame. A detector matching under ~60% of non-empty lines declines rather than half-colouring. Colour must never imply structure that is not there. Same treatment reaches Codex commandExecution, opencode bash and pi bash for free: it lives in the shared body, not the Claude map.

6 · Gate findings — behaviour, not pixels

  • TodoWrite.isEnabled is !z_() && mL() — off whenever the Tasks system is on, which is the default. Its replacement (TaskCreate/TaskGet/TaskList/TaskUpdate) needs CLAUDE_CODE_ENABLE_TODO_TOOLS=true, which ClaudeUI never sets: today a Claude session has no checklist tool at all. Setting it in buildEnv revives the widget with no renderer change — derive-session.ts and HIDDEN_TOOLS already handle the family.
  • AskUserQuestion and ExitPlanMode are gated on Ae() && gWe(wH()) — non-interactive and a permission-prompt tool configured. ClaudeUI passes --permission-prompt-tool stdio, so both live; a spawn without it loses plan mode's exit tool silently. Worth a buildArgs guard test.
  • MultiEdit no longer exists in 2.1.268 — ClaudeEngineToolMap still maps it. BashOutput/KillShell are now aliases of TaskOutput/TaskStop.
